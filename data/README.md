# data/

Authored, committed data (ADR 005). `library/` is generated by import; this folder is written by hand
or by the studio, and reviewed as a diff.

| Path | What | Validated by (`@guildhall/assets`) |
|---|---|---|
| `recipes/{houses,landmarks,stalls,docks,farm}/<id>.json` | prefab recipes | `validatePrefab` |
| `mounts.json` | `{ version: 1, mounts: Record<catalogId, Mount> }` (ADR 010) | `validateMounts` |
| `npcs/<role>.json` | NPC recipes | `validateNpc` |
| `towns/<preset>.json` | town presets (`TownSpec`) | an object, until the world package has a validator |

File names are kebab-case ids. Files hold sorted keys, 2-space indentation, every object and array
expanded, and a final newline; biome enforces the same shape here (`biome.json`, `data/**`).

## The studio endpoint

The studio's vite server (`apps/studio/vite.config.ts`) serves this folder at `/data/`:

- `GET /data/<folder>/` lists the ids in a folder (`[]` when it does not exist yet);
- `GET /data/<path>.json` reads one file (dev and preview);
- `PUT /data/<path>.json` writes one file, in the dev server only.

A write must be a JSON body (`Content-Type: application/json`, at most 1 MiB) sent from this machine
to one of the paths above. It is checked by the validator for its folder (422 with the problems when
it fails), then written atomically. Nothing outside these paths is served or written, and symlinks
under `data/` are refused. `apps/studio/src/data.ts` is the client.
